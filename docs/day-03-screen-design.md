# 3일차 — PC·모바일 화면 설계

회사: (주)인지아이앤에스  
작성일: 2026-09-23  
기준: [2일차 방문 흐름·콘텐츠 기획](day-02-customer-flow-and-content.md)  
상태: 화면 구조와 동작 설계 완료. 실제 Next.js 구현·상담 접수 연결 전 단계.

## 1. 전체 화면 구조

한 페이지에 내용을 배치하고, 상단 메뉴는 페이지 내부의 해당 영역으로 이동한다. 로고가 준비되기 전에는 회사명을 텍스트로 표시한다.

사용자 수정 반영: 상단 회사명은 왼쪽 정렬하고 화면 왼쪽에서 16px 여백을 둔다. PC 메뉴와 모바일 메뉴 버튼은 오른쪽에 배치한다. 이 상단 여백은 아래 본문 여백과 별도로 적용한다.

| 순서 | 영역 | PC 배치 | 모바일 배치 |
| --- | --- | --- | --- |
| 1 | 상단 메뉴 | 회사명 왼쪽, 메뉴·도입 상담 오른쪽 | 회사명 왼쪽, 메뉴 열기 버튼 오른쪽 |
| 2 | 첫 화면 | 제목·설명·버튼 왼쪽, QMS 관리 범위 요약 오른쪽 | 제목 → 설명 → 버튼 → 관리 범위 요약 |
| 3 | 서비스 | 분석·설계 / 개발·구축 / 운영·유지보수 3열 | 같은 순서로 1열 |
| 4 | 주요 기능 | 기능명 왼쪽, 업무 설명 오른쪽의 5개 행 | 기능명 아래 설명을 배치 |
| 5 | 구축 절차 | 5단계 순서 목록, 공간 부족 시 줄바꿈 | 번호가 있는 세로 목록 |
| 6 | 회사 소개 | 회사 설명과 상담 전화 2열 | 회사 설명 다음 전화 |
| 7 | 상담 문의 | 안내·전화 왼쪽, 문의 양식 오른쪽 | 안내 → 전화 → 문의 양식 |
| 8 | 하단 | 회사명, 전화, 개인정보 안내 | 항목을 줄바꿈해 표시 |

첫 화면의 관리 범위 요약은 문서·심사·시정조치의 관계를 설명하는 구성도다. 가상 실적이나 실시간 대시보드 수치를 넣지 않는다.

## 2. 크기와 반응형 기준

- 기본 본문: 16px 이상, 설명은 충분한 줄 간격을 적용한다. 작은 보조 표시는 14px을 기준으로 한다.
- 콘텐츠 최대 너비: 1,200px. PC 좌우 여백 32px, 모바일 20px을 기본으로 한다.
- 1,024px 이상: PC 메뉴, 2~3열 구성.
- 768~1,023px: 접이식 메뉴, 서비스 2열, 긴 영역은 순서대로 줄바꿈.
- 767px 이하: 접이식 메뉴, 모든 주요 영역과 양식 1열.
- 고정 높이로 본문을 자르지 않는다. 한국어 문장을 읽기 쉬운 위치에서 줄바꿈한다.
- 버튼은 최소 44px 높이, 모바일 첫 화면의 두 버튼은 세로로 배치한다.
- 320px 화면과 글자 200% 확대를 구현 단계의 확인 기준에 포함한다.
- 색상·이미지·최종 서체는 5~6일차 디자인에서 확정한다. 이번 설계도는 배치 검토용이다.

## 3. 메뉴와 버튼 동작

| 요소 | 표시 문구 | 동작 |
| --- | --- | --- |
| 회사명 | (주)인지아이앤에스 | 페이지 상단으로 이동 |
| 메뉴 | 서비스 / 주요 기능 / 구축 절차 / 회사 소개 | 각각의 영역으로 이동 |
| 상단·첫 화면 주요 버튼 | 도입 상담 / QMS 도입 상담 | 문의 영역으로 이동 |
| 첫 화면 보조 버튼 | 주요 기능 보기 | 주요 기능 영역으로 이동 |
| 상담 전화 | 010-4103-1467 | 전화 연결 링크 실행 |
| 모바일 메뉴 버튼 | 메뉴 / 닫기 | 헤더 아래 메뉴를 열고 닫음 |
| 하단 개인정보 안내 | 개인정보 처리방침 | 운영 기준 확정 후 실제 안내 화면 연결 |

모바일 메뉴는 페이지 위에 겹치는 대화상자 대신 본문을 아래로 밀어내는 방식이다. 항목 선택 시 닫고 해당 영역으로 이동한다. Escape 키로 닫으면 메뉴 버튼으로 초점을 돌린다. 버튼에 열림 상태와 대상 메뉴를 연결한다. 큰 화면 전환 시 모바일 열림 상태를 초기화한다.

고정 헤더를 적용할 경우 이동한 제목이 헤더에 가리지 않게 여백을 확보한다. 화면 설계도에서는 헤더를 고정하지 않는다. 실제 구현에서는 영역 이동 후 목적지 제목에 초점을 주어 키보드 사용자도 위치를 알 수 있게 한다.

## 4. 첫 화면 우선순위

1. 대상: 품질관리 기업을 위한 QMS 맞춤 개발.
2. 분야: ISO 9001 · IATF 16949.
3. 제목: 품질관리 업무를 하나의 QMS로.
4. 설명: 고객사별 문서, 심사 일정, 부적합과 시정조치를 연결하는 맞춤 개발 서비스.
5. 행동: QMS 도입 상담 / 주요 기능 보기.
6. 보조 구성도: 고객사별 문서·승인, 심사·증빙, 부적합·시정조치.

상담 버튼은 첫 화면과 상단 메뉴에 두고, 본문 각 행에 반복 배치하지 않는다. 로그인·무료 체험은 이번 홈페이지에 포함하지 않는다.

## 5. 상담 양식 배치

| 순서 | 항목 | 필수 여부 | 형태·PC 배치 |
| --- | --- | --- | --- |
| 1 | 회사명 | 필수 | 한 줄 입력, 담당자명과 같은 행 |
| 2 | 담당자명 | 필수 | 한 줄 입력 |
| 3 | 회신용 이메일 | 필수 | 이메일 입력, 전화번호와 같은 행 |
| 4 | 전화번호 | 선택 | 전화번호 입력 |
| 5 | 관심 기능 | 선택 | 6개 체크박스, 여러 개 선택 가능 |
| 6 | 희망 구축 시기 | 선택 | 짧은 자유 입력, ‘미정’ 허용 |
| 7 | 문의 내용 | 필수 | 여러 줄 입력, 전체 너비 |
| 8 | 개인정보 안내·동의 | 공개 전 운영 기준 확정 | 안내와 필요한 동의를 제출 직전에 배치 |
| 9 | 제출 | 해당 없음 | 상담 요청 보내기 |

관심 기능: 문서·승인 / 심사·인증 업무 / 부적합·시정조치 / 고객사·협력사 대응 / 고객사별 현황 / 기타·상담 후 결정.

모바일은 문서에 적힌 순서 그대로 한 열로 표시한다. 모든 입력은 항상 보이는 라벨을 사용하고, 필수·선택을 글자로 구분한다. 체크박스 선택 영역도 최소 44px 높이를 확보한다.

## 6. 문의 상태별 설계

| 상태 | 화면 처리 |
| --- | --- |
| 기본 | 입력 안내와 필수 표시, 전화 상담 경로 제공 |
| 입력 오류 | 잘못된 항목 아래 구체적인 설명, 첫 오류 항목으로 초점 이동 |
| 접수 중 | 제출 버튼 ‘보내는 중…’, 중복 제출 방지, 상태 읽기 지원 |
| 성공 | 실제 저장 확인 후 접수 완료 안내, 이때만 입력 초기화 가능 |
| 실패 | 입력 유지, 다시 시도 안내, 상담 전화 제공 |

화면 설계도는 실제 문의를 수집하거나 전송하지 않는다. 양식을 비활성화하고 ‘화면 설계용 · 상담 접수는 아직 연결되지 않았습니다’라고 표시한다. 개인정보 운영 문구가 미정인 상태에서 임의 동의 문구를 만들지 않는다.

## 7. 콘텐츠와 접근성 확인 기준

- 제목은 첫 화면에 하나의 최상위 제목, 이후 영역에 하위 제목을 사용한다.
- 메뉴, 버튼, 입력 순서가 화면 읽는 순서와 일치한다.
- 초점 표시를 숨기지 않고, 펼침 상태와 입력 오류를 보조 기술로도 전달한다.
- 색상만으로 필수·오류·선택 상태를 구분하지 않는다.
- 근거 없는 인증·실적·개선율과 고객사 로고를 표시하지 않는다.
- 실제 개발 범위는 협의 후 결정함을 기능 소개에 표시한다.
- 회사명은 (주)인지아이앤에스, 전화는 010-4103-1467로 통일한다.

## 8. 산출물과 다음 일정

이번 산출물은 본 화면 설계 문서와 대화에서 확인하는 PC·모바일 배치 시안이다. 시안은 메뉴 이동과 펼침 동작만 확인하는 설계용이며 홈페이지 배포 결과물이 아니다.
