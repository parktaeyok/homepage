## 1. 홈페이지 역할

품질관리 회사와 컨설팅 기업이 ISO 9001 및 자동차 분야 IATF 16949 관련 업무를 관리할 QMS를 검토하고, 맞춤 개발 상담을 요청하도록 돕는다.

이번 홈페이지는 QMS 개발·구축·운영 서비스를 소개한다. 실제 고객사 로그인과 품질 업무 처리 화면은 후속 시스템 개발 범위다. 기술 구성은 1일차에 정한 Next.js, GitHub, Vercel, Supabase를 유지한다.

## 2. 주요 방문자와 확인할 내용

| 방문자 | 도입 검토 상황 | 홈페이지에서 먼저 확인할 내용 |
| --- | --- | --- |
| 품질관리 회사 대표 | 여러 고객사의 업무를 일관된 방식으로 관리하고 싶음 | 고객사별 관리와 맞춤 개발 범위 |
| 품질·인증 업무 책임자 | 문서, 심사 일정, 시정조치를 연결해 관리하고 싶음 | 관리 기능과 업무 흐름 반영 방식 |
| 시스템 도입 담당자 | 필요한 기능과 구축 진행 방식을 정리하고 싶음 | 구축 절차, 상담 준비 항목, 운영 지원 범위 |

자동차 제조사·부품 협력업체의 품질 업무를 사례 맥락으로 사용한다. 제조사 직접 영업 여부는 아직 확정하지 않았으므로 품질관리 기업을 우선 대상으로 표현한다.

## 3. 고객 방문 흐름

기본 흐름: 서비스 인지 → 필요한 기능 확인 → 구축 방식 확인 → 제공 회사 확인 → 상담.

| 순서 | 방문자의 질문 | 제공할 내용 | 다음 행동 |
| --- | --- | --- | --- |
| 1. 첫 화면 | 우리 회사에 필요한 서비스인가? | 대상 고객, 인증 분야, QMS 맞춤 개발 소개 | 주요 기능 보기 또는 도입 상담 |
| 2. 서비스 | 무엇을 맡길 수 있는가? | 업무 분석, 맞춤 개발, 운영·유지보수 | 필요한 기능 확인 |
| 3. 주요 기능 | 현재 업무를 어떻게 관리할 수 있는가? | 문서·심사·시정조치·고객사별 관리 예시 | 구축 절차 확인 |
| 4. 구축 절차 | 어디서부터 준비해야 하는가? | 상담부터 운영까지의 단계와 준비 자료 | 회사 정보 또는 상담 확인 |
| 5. 회사 소개 | 누가 개발하고 운영하는가? | 확인된 회사명, 서비스 분야, 연락처 | 상담 요청 |
| 6. 상담 | 어떤 내용을 전달하면 되는가? | 문의 양식과 전화 안내 | 접수 또는 전화 연결 |

서비스를 이미 알고 방문한 고객은 상단의 ‘도입 상담’에서 곧바로 문의 영역으로 이동할 수 있게 한다.

## 4. 메뉴와 콘텐츠 순서

초기 홈페이지는 한 페이지 안에 내용을 순서대로 배치하는 구성을 제안한다. 정보량이 늘면 상세 페이지로 확장한다. 개인정보 안내는 문의 기능 구현 시 운영 기준에 맞춰 별도로 구성한다.

- 상단: 회사명 / 서비스 / 주요 기능 / 구축 절차 / 회사 소개 / 도입 상담.
- 본문: 첫 화면 → 서비스 → 주요 기능 → 구축 절차 → 회사 소개 → 상담 문의.
- 하단: 회사명, 상담 전화, 개인정보 안내.
- 모바일: 회사명과 메뉴 버튼을 표시하고, 상담 영역의 전화번호를 눌러 전화할 수 있게 한다.

## 5. 첫 화면 문구 초안

대상 표시: **품질관리 기업을 위한 QMS 맞춤 개발**

제목:

> ISO 9001 · IATF 16949
> 품질관리 업무를 하나의 QMS로

설명:

> 고객사별 문서, 심사 일정, 부적합과 시정조치를 연결합니다.
> (주)인지아이앤에스가 귀사의 업무 흐름에 맞춰 QMS를 설계하고 개발합니다.

버튼:

- ‘QMS 도입 상담’: 상담 문의 영역으로 이동.
- ‘주요 기능 보기’: 기능 소개 영역으로 이동.

인증 취득이나 표준 준수 전체를 보장하는 표현은 사용하지 않는다. 기능은 맞춤 개발 가능 범위로 소개하고, 기존 제품으로 이미 제공 중이라는 인상을 주지 않는다.

## 6. 서비스 소개 문구 초안

영역 제목: **업무 분석부터 구축 후 운영까지**

| 서비스 | 소개 문구 | 상담에서 구체화할 내용 |
| --- | --- | --- |
| 업무 분석·시스템 설계 | 현재 사용하는 문서와 업무 절차를 살펴보고, 고객사별 관리 기준과 담당자별 처리 흐름을 설계합니다. | 현재 관리 방식, 사용자, 문서 양식, 우선 과제 |
| QMS 맞춤 개발·구축 | 문서 관리, 심사 일정, 부적합 및 시정조치 등 필요한 기능을 업무 우선순위에 맞춰 개발합니다. | 기능 범위, 승인 단계, 데이터 이전·연동 필요 여부 |
| 운영·유지보수 | 구축 후 사용 과정에서 필요한 수정과 기능 개선을 지원합니다. 구체적인 지원 범위는 계약 시 정합니다. | 지원 창구, 유지보수 범위, 교육 및 개선 요청 방식 |

고정 가격, 구축 소요 기간, 상시 대응 시간은 근거가 없으므로 제시하지 않는다. 홈페이지 제작 15영업일 일정은 고객에게 판매할 QMS 구축 기간과 별개다.

## 7. 주요 기능 소개 문구 초안

영역 제목: **귀사의 품질 업무에 맞춰 구성하는 관리 기능**

| 기능 | 고객의 관리 과제 | 공개 문구 초안 |
| --- | --- | --- |
| 문서·승인 관리 | 최신 문서와 검토·승인 이력을 확인하기 어려움 | 품질 문서의 개정 이력과 검토·승인 상태를 함께 확인하도록 구성합니다. |
| 심사·인증 업무 관리 | 고객사별 일정과 준비 자료가 분산됨 | 심사 일정, 체크리스트, 증빙 자료와 후속 조치를 연결해 관리하도록 구성합니다. |
| 부적합·시정조치 관리 | 원인 분석 이후 조치 완료 여부를 추적하기 어려움 | 문제 등록부터 원인 분석, 개선 조치, 효과 확인까지 진행 상태를 관리하도록 구성합니다. |
| 고객사·협력사 대응 | 클레임과 개선대책의 담당자·기한이 흩어짐 | 고객사별 요청과 대응 이력, 담당자 및 처리 기한을 정리하도록 구성합니다. |
| 고객사별 현황 관리 | 여러 고객사의 진행 상태를 한 번에 파악하기 어려움 | 고객사별 일정과 미완료 업무, 주요 관리 항목을 한눈에 확인하도록 구성합니다. |

모든 기능을 기본 제공한다고 표시하지 않는다. 실제 개발 범위는 상담을 통해 결정한다. 표준 조항별 적합성 설명과 전문 인증 해석은 이 초안의 범위에 포함하지 않는다.

화면 예시를 추가하는 경우 가상의 고객사명과 데이터를 사용하고 ‘QMS 구성 예시 · 실제 개발 범위는 협의 후 결정’이라고 표시한다. 미구현 기능으로 이동하는 로그인·체험 버튼은 만들지 않는다.

## 8. 구축 절차 소개

| 단계 | 홈페이지 설명 | 고객 준비 사항 |

| 2. 시스템 설계 | 화면, 관리 항목과 업무 처리 흐름을 정리합니다. | 검토 담당자, 사용 양식과 승인 절차 |

| 5. 교육·운영 | 사용 방법을 안내하고 합의한 범위에서 운영을 지원합니다. | 운영 담당자와 지원 방식 협의 |

## 10. 상담 흐름과 문구

제목: **어떤 품질 업무를 관리하고 싶으신가요?**

설명: **현재 관리 방식과 필요한 기능을 알려주시면 QMS 구축 범위를 함께 정리하겠습니다.**

- 필수 항목: 회사명, 담당자명, 회신용 이메일, 문의 내용.
- 선택 항목: 전화번호, 관심 기능, 희망 구축 시기.
- 관심 기능 선택지: 문서·승인 / 심사·인증 업무 / 부적합·시정조치 / 고객사·협력사 대응 / 고객사별 현황 / 기타·상담 후 결정.
- 문의 내용 안내: ‘현재 관리 방식, 필요한 기능, 예상 사용자 수 등을 적어주세요.’
- 제출 버튼: ‘상담 요청 보내기’.
- 전화 안내: ‘전화 상담 010-4103-1467’.

| 상태 | 표시할 내용과 동작 |
| --- | --- |
| 입력 오류 | 해당 항목 아래에 누락·형식 오류를 안내하고 입력 내용은 유지 |
| 접수 중 | ‘보내는 중…’ 표시, 중복 제출 방지 |
| 저장 성공 | 실제 저장이 확인된 경우에만 ‘상담 요청이 접수되었습니다.’ 표시 |
| 저장 실패 | ‘접수하지 못했습니다. 다시 시도하거나 010-4103-1467로 전화해 주세요.’ 표시, 입력 내용 유지 |

개인정보 안내·동의 세부 문구, 보관 기간과 운영 담당자는 접수 기능 공개 전에 확정한다. 확인되지 않은 회신 시간이나 자동 이메일 발송을 약속하지 않는다.
